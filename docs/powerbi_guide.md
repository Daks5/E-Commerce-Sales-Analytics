# Power BI guide

Open `powerbi/CommercePulse.pbix` for the completed dark dashboard or `powerbi/CommercePulse.pbip` to edit its definitions. The report contains Sales pulse, Product drivers, Market demand and Operations pages, 45 explicit measures, five authored tables and four single-direction star relationships. The earlier SalesAnalytics version remains available locally.

The model imports `data/powerbi/*.csv`, exported from the actual MySQL database after cleaning. This allows the report to refresh without storing database passwords inside it. The native MySQL connector remains installed for later direct-connection work.

If moving the project folder, edit the `ProjectRoot` Power Query parameter to the new folder. Refresh in Desktop after a SQL pipeline run. The PBIP contains definitions; the saved PBIX contains a refreshed snapshot and can be opened without a running MySQL server. Refresh requires the local CSV exports. Delivery and visual inspection evidence is recorded in `reports/dashboard_redesign_completion.json` and the README.

Use Reporting month, Product category, Fulfillment and Customer type slicers to explore each page. Filters are configured to synchronize across all four pages. Use the normal page tabs to navigate; in Desktop edit mode, use Ctrl + click on the report's navigation buttons. Clear a slicer with its eraser icon or by deselecting the chosen item. Standard measures respond to filter context. The fixed May/June 1–29 comparison measures intentionally remove Date filters while retaining other dimensions. Channel comparison cards remove the Fulfillment filter to show both channels side by side. Clear slicers before comparing overall totals with SQL. Rates use line denominators; distinct orders are not additive across products.

All amounts are INR. Large totals use crore (Cr), and category changes use lakh (L). Shipped value uses the eligibility rule in `docs/metric_contract.md`; recorded amount on Operations includes every status. Unknown and unmapped geography remain visible. Six duplicate copies are excluded before import and remain in the MySQL/Python audit. Missing amounts stay missing. Snapshot completeness, profitability, collected revenue and causality are not established by this dataset.

Source structure follows Microsoft's documented PBIR project format. Generated definitions passed the official schemas before Desktop save. Desktop advanced some saved definitions to visualContainer 2.13.0; the corresponding public schema returned HTTP 404, so post-save schema validation could not be completed. The actual report passed native Desktop inspection and DAX verification.

All four pages were inspected in Desktop on 6 October 2026. Kurta selected on Operations carried to Sales pulse and displayed ₹1.89 Cr and 38,682 valued orders. Selecting March changed normal KPIs while the fixed comparison stayed at −6.7%. Business (B2B) displayed 718 valued orders; Merchant displayed a 17.5% cancelled-line rate. All slicers were cleared before saving, and the report opens on Sales pulse. Actual captures are in `reports/screenshots_dark/`.

Rebuild with `src/build_dark_powerbi.py`, then prepare expected results with `src/prepare_dark_validation.py`. Rebuilding resets native inspection status to pending: open the PBIP, refresh, inspect and save it before replacing the delivered PBIX. Desktop may update report schema versions on save. Design and detailed filter rules are in `dashboard_redesign.md`.

The executed DAX verification is in `reports/powerbi_dark_engine_validation.json`: all 45 measures compile without errors, and 141 checks reconcile totals, dimensions, category changes and 29 aligned daily values with SQL-derived expectations. To rerun against an open local Desktop model, prepare Microsoft's client libraries with `.venv\Scripts\python.exe src\prepare_as_sdk.py`, then run `pwsh -File src\verify_dark_powerbi.ps1 -Port <local-model-port>`. The local Analysis Services port changes between Desktop sessions; it is not the MySQL port.
